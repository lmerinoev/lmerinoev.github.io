4.1The idea

After pretraining, a model is usually trained on example conversations written by people. This is supervised fine-tuning (SFT), and it uses the same cross-entropy loss as pretraining. The SFT model can follow instructions, but there is no single correct answer to most prompts, and some good answers are better than others.

People find it hard to give an answer a score out of 10, and two people rarely agree on the number. They find it much easier to read two answers to the same prompt and say which is better. So the training data is a collection of preference pairs: a prompt, the response a rater picked, and the response they passed over.

A reward model is a neural network that reads a prompt and a response and outputs a single number, its reward. Training should make the picked response get the higher number. In InstructGPT, the reward model started as a copy of the SFT model with its final layer replaced by one that outputs a single number.

4.2Bradley-Terry

The Bradley-Terry model (Bradley and Terry, 1952) says how scores turn into choice probabilities. The DPO paper writes it like this:

P({y_w} \succ {y_l} \mid {x}) = \frac{{\exp}\big({r_\phi}({x}, {y_w})\big)}{{\exp}\big({r_\phi}({x}, {y_w})\big) + {\exp}\big({r_\phi}({x}, {y_l})\big)}
(4.1)

That is a two-way softmax (Module 2), which equals the sigmoid of the difference:

P({y_w} \succ {y_l} \mid {x}) = {\sigma}\big({r_\phi}({x}, {y_w}) - {r_\phi}({x}, {y_l})\big)
(4.2)

Read it as: take the reward of the preferred response, subtract the reward of the rejected one, and pass the difference through the sigmoid. Only the difference matters. Adding 100 to both rewards leaves the probability unchanged.

4.3The loss

Training adjusts φ to make the raters' choices as probable as possible. For one preference pair the loss is the negative log of equation 4.2:

\mathcal{L}({\phi}) = -{\log}\,{\sigma}\big({r_\phi}({x}, {y_w}) - {r_\phi}({x}, {y_l})\big)
(4.3)

This is the cross-entropy loss from Module 2 applied to a yes-or-no question: did the model give the rater's choice a high probability?

Over a dataset \mathcal{D} of pairs, training minimizes the average (DPO, equation 2):

\mathcal{L}_R({r_\phi}, \mathcal{D}) = -\mathbb{E}_{({x}, {y_w}, {y_l}) \sim \mathcal{D}}\Big[{\log}\,{\sigma}\big({r_\phi}({x}, {y_w}) - {r_\phi}({x}, {y_l})\big)\Big]
(4.4)

InstructGPT's equation 1 is the same loss with one difference. Raters there ranked between 4 and 9 responses at once, which gives several pairs per prompt, and the loss is divided by the number of pairs so each prompt counts once. InstructGPT writes the reward model as rθ. This site uses rφ, as the DPO paper does, and keeps θ for the language model being tuned.

Because only differences matter, the loss cannot pin down the overall level of the rewards. InstructGPT shifted its reward model so that the human-written demonstrations scored 0 on average.

4.5Exercises

  1. Both responses get a reward of 3.0. What probability does equation 4.2 give to the preferred one?

    0.5. The gap is 0 and σ(0) = 1/(1 + 1) = 0.5, so the model has no preference.

  2. The preferred response scores 1.0 and the rejected one scores 2.0. Is the loss above or below 0.693, which is −log 0.5?

    Above. The gap is −1.0, σ(−1.0) ≈ 0.269, and −log 0.269 ≈ 1.31. The model ranked the pair the wrong way round, so the loss is large.

  3. Why collect comparisons instead of asking raters for a score out of 10?

    Raters use a 1 to 10 scale differently from one another, but they agree much more often about which of two answers is better.

  4. You add 5 to every reward the model outputs. What happens to the loss?

    Nothing. The loss depends only on the difference between two rewards, and adding the same amount to both leaves the difference unchanged.

  5. Show that equation 4.1 equals equation 4.2. Write a and b for the two rewards.

    Divide the top and bottom of exp(a)/(exp(a) + exp(b)) by exp(a). That gives 1/(1 + exp(b − a)) = 1/(1 + e−(a − b)) = σ(a − b).
