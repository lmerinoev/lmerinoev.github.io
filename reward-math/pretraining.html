2.1Text as tokens

A language model does not read letters or whole words. Text is first split into tokens, chunks that are often a word or part of a word. A rare word might be split into several pieces, while a common word is usually one token. The fixed list of every token the model knows is its vocabulary, usually tens of thousands to a few hundred thousand entries. The program that does the splitting is the tokenizer.

A language model reads a sequence of tokens and outputs, for every token in the vocabulary, the probability that it comes next. Those numbers form a probability distribution: each is between 0 and 1, and together they add up to 1.

2.2Predicting the next token

Write a piece of text as tokens x_1, x_2, \dots, x_T. The tokens before position t are written x_{<t} and called the context. The probability of the whole text splits into one prediction per position:

p_{{\theta}}(x_1, \dots, x_T) = \prod_{t=1}^{T} p_{{\theta}}(x_t \mid x_{<t})
(2.1)

This is next-token prediction. A model that is good at guessing each token from the ones before it assigns high probability to realistic text. It is also how the model writes: it picks a next token from its distribution, appends it, and repeats.

2.3Logits and softmax

The network's last layer produces one raw score per vocabulary entry, called a logit. The softmax function turns those scores into a probability distribution:

p_{{\theta}}(x_t = i \mid x_{<t}) = \frac{{\exp}(z_i)}{\sum_{j} {\exp}(z_j)}
(2.2)

With only two options, softmax is the sigmoid from Module 1 applied to the difference of the two logits: exp(a)/(exp(a) + exp(b)) = σ(a − b). That fact comes back in Module 4.

2.4The cross-entropy loss

Pretraining shows the model a very large amount of text and asks it to predict every token from the ones before. The loss is:

\mathcal{L}({\theta}) = -\sum_{t} {\log}\, p_{{\theta}}(x_t \mid x_{<t})
(2.3)

This is the cross-entropy loss, also called the negative log-likelihood. It uses the log probability \log p instead of p for two reasons. Logs turn the product in equation 2.1 into a sum, and a product of thousands of small probabilities is too small for a computer to store accurately. Minimizing this loss is the same as making the training text as probable as possible.

-\log p is 0 when p = 1 and grows without limit as p approaches 0, so a confident wrong guess costs far more than a hesitant one. In practice the loss is averaged over every token in a batch and minimized with gradient descent, with backpropagation running through the whole network.

2.5A worked example

A toy vocabulary has four tokens: “the”, “cat”, “sat” and “mat”. Given the context “the cat”, the network outputs the logits below. The actual next token in the training text is “sat”.

tokenlogit zexp(z)probability−log p
the0.51.64870.12822.0542
cat0.11.10520.08592.4542
sat (actual)2.07.38910.57450.5542
mat1.02.71830.21141.5542

The exponentials add up to 12.8612, and each probability is its exponential divided by that total.

The loss at this position is -\log 0.5745 = 0.554. A model that knew nothing and gave each token 0.25 would have loss -\log 0.25 = \log 4 \approx 1.386, so this model does better than chance. A gradient step would raise the logit for “sat” and lower the others.

2.6Exercises

  1. The model gives the correct next token probability 1. What is the loss at that position?

    0, because log 1 = 0.

  2. One model gives the correct token probability 0.1, another gives it 0.01. How much higher is the second model's loss?

    −log 0.01 = 4.605 and −log 0.1 = 2.303, so 2.303 higher. That is log 10: every factor of ten less probability adds about 2.3 to the loss.

  3. A model with a 50,000-token vocabulary guesses uniformly. What is its loss per token?

    Each token gets probability 1/50,000, so the loss is log 50,000 ≈ 10.82 per token. A trained model must do much better than this.

  4. Why add up log probabilities instead of multiplying probabilities?

    The product of thousands of probabilities is too small to store accurately (it underflows to 0). The log turns the product into a sum, which is stable to compute and whose gradient is the sum of the gradients of each term.
