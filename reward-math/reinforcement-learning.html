3.1Agents and environments

Pretraining has a correct answer at every position. Many problems do not: you only learn afterwards whether a whole series of choices went well. Reinforcement learning (RL) is learning from that kind of feedback.

The learner is the agent, and everything it interacts with is the environment. At each time step t the agent sees a state s_t, picks an action a_t, and receives a reward r_t, a number saying how good that was. The rule the agent uses to choose actions is its policy. A policy with parameters θ is written {\pi_\theta}, and {\pi_\theta}(a \mid s) is the probability that it picks action a in state s.

The record of states, actions and rewards from one run is a trajectory, written τ (tau). One complete run from start to finish is an episode.

For a language model the mapping is direct. The state is the prompt plus the tokens written so far, an action is the next token, and the policy is the language model itself. In the training covered by later modules, the reward usually arrives once, after the whole response is written.

3.2Return

The return adds up the rewards along a trajectory:

R(\tau) = \sum_{t=0}^{T} \gamma^{t}\, r_t
(3.1)

The discount factor γ makes later rewards count less when it is below 1. With γ = 1 the return is the plain sum. Language model training commonly uses γ = 1, since the episode is one short response.

3.3Expected return

Both the policy and the environment can be random, so one policy produces many different trajectories. The expected value, written 𝔼, is the average over all possible outcomes, weighted by their probabilities. The expected return of a policy is what RL tries to maximize:

J({\theta}) = \mathbb{E}_{\tau \sim {\pi_\theta}}\big[R(\tau)\big]
(3.2)

Spinning Up calls maximizing this “the RL problem”.

3.4The policy gradient

We want the gradient of J so we can climb it. The difficulty is that θ affects J only through which actions get sampled, and you cannot take a derivative through a random draw directly. The policy gradient rewrites the gradient as something you can estimate from samples:

\nabla_{{\theta}} J({\theta}) = \mathbb{E}_{\tau \sim {\pi_\theta}}\Big[\sum_{t=0}^{T} \nabla_{{\theta}} {\log} {\pi_\theta}(a_t \mid s_t)\, R(\tau)\Big]
(3.3)

Read it as: for each action taken, push up its log probability in proportion to how good the outcome was. Actions in good trajectories become more likely and actions in bad ones less likely. This form is derived in Spinning Up, part 3.

3.5REINFORCE

REINFORCE (Williams, 1992) uses this directly: run an episode, then update with what happened. In Sutton and Barto's form (their equation 13.8, written with the log as in their pseudocode):

{\theta} \leftarrow {\theta} + \alpha\, G_t\, \nabla_{{\theta}} {\log} {\pi_\theta}(a_t \mid s_t)
(3.4)

G_t counts only rewards from step t onward, because an action cannot affect rewards that came before it. Sutton and Barto index rewards so that R_{t+1} follows action A_t. The idea is the same.

3.6Baselines and advantages

If every reward is positive, every sampled action gets pushed up, only by different amounts. Learning is then slow and noisy. The fix is to subtract a baseline b, an estimate of the usual return, and push by G_t - b instead. Actions that did better than usual go up and worse ones go down. Better than expected by how much is called the advantage:

A_t = G_t - b(s_t)
(3.5)

A baseline that does not depend on the action leaves the average gradient unchanged while reducing its noise. Spinning Up proves this with what it calls the expected grad-log-prob lemma.

3.7A worked example

One state and two actions, A and B. Action A always gives reward 1 and B gives 0. The policy is a softmax over two preferences {\theta_A} and {\theta_B}, both starting at 0, so \pi(A) = \pi(B) = 0.5. For a softmax policy, the gradient of \log \pi(a) with respect to preference \theta_k is 1 - \pi(k) when k = a and -\pi(k) otherwise. Use step size \alpha = 1.

  1. sample A, G = 1 ∇log π(A) = (1 − 0.5, −0.5) = (0.5, −0.5)
  2. update θ = (0, 0) + 1 × 1 × (0.5, −0.5) = (0.5, −0.5)
  3. new policy π(A) = e0.5 / (e0.5 + e−0.5) = σ(1) = 0.731

If B had been sampled instead, G = 0 and nothing would change. Half the episodes would teach nothing. Now add a baseline b = 0.5, the average reward under the starting policy:

  1. sample B, A = 0 − 0.5 = −0.5 ∇log π(B) = (−0.5, 0.5)
  2. update θ = (0, 0) + 1 × (−0.5) × (−0.5, 0.5) = (0.25, −0.25)
  3. sample A, A = 1 − 0.5 = 0.5 θ = (0, 0) + 0.5 × (0.5, −0.5) = (0.25, −0.25)
  4. either way π(A) = σ(0.5) = 0.622

With the baseline, every episode moves the policy toward A, by the same amount whichever action was sampled. The updates are smaller but far less noisy.

3.8Exercises

  1. For a language model, what are the state, the action and the policy?

    The state is the prompt plus the tokens generated so far. An action is the next token. The policy is the language model, whose output distribution gives the probability of each next token.

  2. In the worked example without a baseline, action B is sampled. How does the policy change?

    It does not. The return is 0, so equation 3.4 adds 0 × (gradient).

  3. Why does RL maximize the expected return rather than the return?

    The policy samples its actions and the environment can be random, so the return differs from run to run. The expected return is the average a policy achieves, which is a fixed number we can improve.

  4. Why does REINFORCE weight each action by Gt, the return from step t onward, rather than the whole return R(τ)?

    An action cannot change rewards that arrived before it. Including them adds noise without adding information.

  5. With the baseline, sampling A and sampling B gave the same update. Why is that a good thing?

    The update no longer depends on luck in which action was sampled, so it has less variance. Both outcomes move the policy toward the better action.
